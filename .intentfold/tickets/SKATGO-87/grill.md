# SKATGO-87 grill

Grill：self（人：「开始开发吧，自己grill，等我检阅」）。依据是 charter 和读到的代码；人在开发前对话里说定的事项，视为已定。

1. **哪一步能跳叫？** — 只有报价方。应叫方只回答跟或不跟。两家都 pass 后前手开叫只能叫 18：跳得更高也没有对手要压，反而有叫超的风险。依据：Skat 规则；之前对话里定的「只有报价方需要跳叫」。
2. **展开的这一排列哪些值？** — 下一个值之后的每一档，一直到规则引擎叫牌表（`BID_LADDER`）的最高值 264（Grand Ouvert 能达到的最高值，正式规则也能叫；SkatZero 的上限是 168，电脑遇到超过自己上限的值只会 pass），一排左右滑动，不做「Alle Werte」二级展开。依据：人选了「一排左右滑动」；有了滑动，一排放下全部值就够了，不需要再分两级。
3. **选中和确认** — 点值是选中，再点一次取消；主按钮的数字随之改变，点主按钮才真正叫出。收起这一排时选中也清掉。依据：工单约束「先选中再确认」。
4. **样式** — 值的药丸用现有的 `styles.toggle` / `toggleOn`（`color.goodSoft` 底、`go` 边），不加新 token。依据：ui.md Redline 1。
5. **电脑和提示** — 电脑不跳叫（工单约束）。「Tipp」照旧只建议叫下一个值或 pass，不建议跳叫；课程内容这次不改。依据：工单范围里没有提示和课程。
6. **旧记录兼容** — 没有 `to` 的 bid 动作永远表示下一个值。依据：工单约束。
7. **charter** — 本单没有修改授权。ui.md 若需要描述叫牌区，在 handoff 里报告。
