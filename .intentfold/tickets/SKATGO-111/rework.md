# SKATGO-111 rework

handoff.md 冻结在首次交付（`fa2c520`），人审阅时提的修改如下。

## 1. 左右两家的牌放大

- **人：** 「左右两家的牌，尺寸要和我的手牌一样大，显示大一点，不一定完整显示，但是要大」。
- **改动：** 只改明牌残局，平常打牌时的盖牌不变。
  - **大小：** 左右两家每张牌和手牌一样宽，桌面 130u，手机 96u（原来是 100u / 90u）。
  - **位置：** 牌堆的竖直中心对准出牌框的中心。
  - **每张露多少：**
    - 桌面：每张露出 52u 宽的一条，横向 182u 里有 146u 在牌桌上；
    - 手机：每张露出 46u，横向 134u 里有 56u 在牌桌上，一直到座位牌子旁边；手机上框边位置有限，露不出更多。
  - **新增 token：** `stage.openStackSlot`、`openStackStep`、`openStackInset`，是人这次直接要求的尺寸。
- **测量**（第 1 题，构建版 55111）：
  - 桌面：手牌宽 106px，旁家牌宽 106px；左家牌堆右边在 353，离出牌框（518）很远。
  - 手机：手牌宽 84px，旁家牌宽 84px；牌堆到 61 / 314，离座位牌子（64 / 311）还有 3px，不压出牌框。
  - 两边都没有控制台报错。
- **检查：** typecheck、design tokens、build 通过。

## 2. 出错后由学员自己打完，打完再告诉

- **人：**
  - 「为啥我第一张打了错牌，剩下的都自动替我出完了？」
  - 听了 agent 的解释和建议（当场停下）后：「不停吧，我觉得可以打完，打完后告诉它错了，记下来，但是可以重试。你独立思考看对不对」。
- **agent 的判断：** 同意，补了两点。
  - 出牌时不标对错。否则一出错就知道了，后面的牌白打。
  - 出错后剩下的牌由学员自己出，对手照样按最强打法。比赛到胜负已定就结束，和出对时一样。
- **改动：**
  - **打法树（`open.ts`）：** 每一步学员能出的每张牌都有对手的最强应对，到学员下一次出牌或胜负已定为止。原来只有能赢的牌有后续，出错时由四家一起打到底的反击（`refute`）已删除。
  - **题目数据：** 生成器加了 `--again`，不再重新发牌，从已存的局面重新算打法树：
    - `node --import tsx scripts/make-open-endgames.ts --again`；
    - 20 道题局面不变；
    - 数据文件从 56KB 增加到 135KB。
  - **练习（`open-endgame.tsx`）：**
    - 记下第一张错牌，牌桌上不标对错，也不让能赢的牌发光；
    - 胜负已定时才显示结果卡，同时记录这题对错；
    - 牌桌不再需要 `verdicts`、`glow` 这两个参数，已删除。
  - **结果卡：** 出错时写「Dein Fehler: ♦A. Richtig war ♦B.」（新 `tricks_open_mistake`），删掉不再用的 `tricks_open_here`。
  - **测试：**
    - 走遍每条路：一路出对的最后都赢；只要出过一张错牌，从那以后 `win` 都为空，最后都输；
    - 每一步学员能出的牌都有后续。
- **检查**（桌面，构建版 55111，`tmp/playon.mjs`）：
  - 第 1 题一路出对：3 张，显示「Gelöst! Schlüsselkarte: ♥A」；
  - 第 2 题第一张故意出错（♦A）：结果卡没有马上出现，学员又出了 2 张，到最后显示「Nicht gelöst · Dein Fehler: ♦A. Richtig war ♦B.」；
  - 「Noch mal」重新开始；
  - 目录显示 1 ✓、2 ✗；
  - 没有控制台报错。
  - typecheck（app 和 multiplayer）、exercises 测试 142 项、design tokens、build、client bundle 都通过。
  - `tmp/ac.mjs` 第 3、4 步已按新规则改写，没有重跑。
- **multiplayer：** 只用题目 id，id 没变，不用重新部署。

## 3. 题目页和打牌界面一样全屏

- **人：** 「手机上可以，但是在pc上，有点太，屏幕要滚动，如何能做到打牌界面那种效果，各种尺寸屏幕都刚好全屏」。
- **原因：** 题目页套在网站页面里（顶栏、返回按钮、标题），牌桌高度固定 640px。电脑屏幕不够高时，整页要滚动。
- **改动：**
  - **页面框架（`frame.tsx`）：** `/skat-tricks/offenes-endspiel-*` 改用牌桌框架，和自由对局、每日锦标赛的牌桌一样，不显示网站顶栏，正好一屏、不滚动。
  - **牌桌（`game-table.tsx`）：**
    - 练习也用全屏牌桌，高度 100dvh；牌面元素按屏幕大小一起缩放；
    - 练习没有侧边面板，也没有面板的折叠按钮，而且能在服务端渲染（不读 `window`）；
    - 右上角是牌桌的退出按钮，「Tisch verlassen」回到题目列表。
  - **信息板（`open-endgame.tsx`）：** 顶部一块深色板，样式和打牌界面的信息板一样，从顶边垂下：
    - 「AUFGABE 1 VON 20」；
    - 标题「Karo ♦ · du bist Alleinspieler」，是页面的 h1；
    - 分数条。
  - **题目页（`tricks-exercise-page.tsx`）：**
    - 明牌残局只显示牌桌，原来的返回按钮、题号和标题移到信息板上；
    - 第 3 题起没登录时，牌桌照样摆好，登录卡浮在上面；
    - 账号状态加载完之前不能出牌，也不弹任何卡片。
- **检查**（构建版 55111）：
  - `tmp/fit.mjs`：第 1 题在 1280×720、1440×789、1920×969、1024×640、375×667、390×844 六种尺寸下，页面高度都等于屏幕高度，没有网站顶栏，手牌底边在屏幕内，没有报错。
  - `tmp/gate.mjs`：第 3 题的登录卡浮在牌桌上；退出菜单回到题目列表，列表页顶栏正常。
  - `tmp/playon.mjs` 照样通过（出对、出错后打完、重试、记录）。
  - typecheck、design tokens、build、单元测试 266 项、`check:seo -- --built`、`test:seo` 都通过。
