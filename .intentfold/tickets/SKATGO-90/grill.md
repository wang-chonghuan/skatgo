# SKATGO-90 grill

Grill：human。已经定的：不用邮箱前缀，登录用户也用随机名；词表；写法带空格；数字只在撞名时才加。英文页面也用这些德语名字，因为人同意的就是这份德语词表。

1. **改名后，过去 7 天榜上的名字跟着变吗？**
   - **建议**：跟着变。一个人只有一个名字，所有榜（包括过去 7 天）都用这个名字。
   - **理由**：「一个人一个名字」最简单，不会出现同一个人在不同天叫不同名字的情况。
   - **待定**
2. **改名时，和别人已经在用的名字重了怎么办？**
   - **建议**：拒绝，提示「Dieser Name ist schon vergeben」（这个名字已经有人用了），不分大小写。
   - **理由**：系统给的名字保证不重名，自己改的也应该一样，否则榜上会出现两个一样的名字。
   - **待定**
3. **以前打完了、但从没起过名字的玩家怎么处理？**
   - **建议**：上线时给他们补一个随机名，他们会出现在过去 7 天的榜上。
   - **理由**：新规则是「打完就上榜」；名字是随机的，不暴露身份。
   - **另一种做法**：只对上线之后打完的人生效，过去的榜保持原样。
   - **待定**
4. **charter 要不要在这单里一起改？**
   - **建议**：要，我直接改：
     - product.md、engineering.md：名字按玩家存、打完自动上榜；
     - operations.md：清除昵称的运维命令，改成删掉这个玩家的名字，系统会重新给他一个随机名；
     - ui.md：结果处的「改名」。
   - **理由**：不改的话 charter 会和产品不一致。
   - **待定**

1. 原话：「禁止改变任何已经有的用户的名字，列表里的临时用户填的名字，严格禁止改，这是绝对红线」。
   - **agent 的理解，按红线处理**：
     - 已经存下的名字（`daily_entries.nickname` 里已有的值，包括游客填的），系统在任何情况下都不改：迁移不改，补名字不改，改名也不改过去的。
     - 名字仍按每条记录存（快照），过去几天的榜永远显示当时的名字。
     - 玩家另有一个「当前名字」（`daily_players`），只用来填新打完的记录。
     - 玩家自己改名，只改当前名字和他今天已经打完的记录，和 SKATGO-90 之前「当天午夜前可以改」一样，不碰任何过去的记录。
     - 给以前打完却没名字（NULL）的记录补名字，不算改已有的名字。
   - **待人检阅时确认**：「自己改今天的名字」是否也在禁止之列。
2. **重名就拒绝**：提示「Dieser Name ist schon vergeben」，不分大小写，对比的是其他玩家的当前名字。已经存在的重名保持原样（红线）。
3. **补随机名上榜**：以前打完却没名字的记录，按这个玩家的当前名字补上；他还没有当前名字的，先分一个随机名。
