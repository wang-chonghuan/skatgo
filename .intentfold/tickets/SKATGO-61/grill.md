# SKATGO-61 grill

Grill：human。九个问题一次问完，每个都附建议和理由。背景见 plan.md 开头。

1. **浏览器怎么连房间？要不要新增依赖？**
   - **选项 A（建议）**：沿用 SKATGO-20 的 Colyseus WebSocket 房间。前端新增依赖 `@colyseus/sdk` 0.18.4，与 multiplayer 测试里用的版本一致。
     - engineering.md Redline 3：新增依赖必须由人明确批准，并记在工单里。
   - **选项 B**：不用 WebSocket，像每日赛和自由对局一样走网站转发的 HTTP，每秒轮询对方的出牌。
   - **理由**：
     - charter 的 engineering.md 契约写明房间由 Colyseus 负责，状态走 socket，按座位过滤。选 B 等于另起一套房间实现，和契约冲突，也违背「已有的做法不另起一套」。
     - A 是实时推送，朋友出牌立刻可见；断线重连、按座位过滤的视图、指令回执都已经做好并测过。
   - **待定**
2. **浏览器凭什么进房？**
   - **建议**：网站新增 `/api/room/ticket`，用 admission key 做 HMAC，签发 2 分钟有效的准入票，按地址限频。浏览器拿票直连 multiplayer 的 WebSocket 地址，admission key 永远不进浏览器。
   - **理由**：这正是 SKATGO-20 README 要求后续前端工单做的「服务器签发的短时准入」；不需要新的生产环境变量；限频挡住刷房间。
   - **待定**
3. **邀请链接和「回到原座位」怎么做？**
   - **建议**：
     - 链接形如 `https://skatgo.com/de/raum/<房间号>#<邀请码>`。`#` 后面的部分不会发给任何服务器，也不进日志。
     - 每个人的座位令牌按房间存在浏览器的 localStorage。这是功能必需的存储，不需要 cookie 同意。同一浏览器重开同一链接就回到原座位。
   - **代价**：换一台设备或一个浏览器，就回不到原座位，只能看到「这个房间已经开局」。
   - **待定**
4. **电脑怎么叫牌、出牌？**（工单建议用 SkatZero）
   - **建议**：
     - 房间的牌从自由对局的牌池里取，选发牌人对得上的那一副，座位一一对应。电脑座位的叫牌和拿底或 Hand 用牌池里存好的 SkatZero 方案；扣牌、定约和出牌实时用 SkatZero，与自由对局完全相同。SKATGO-59 的认领和认输也在房间里生效。
     - 牌池只有座位 1、2 的方案；房主的 0 号座如果在叫牌阶段掉线需要电脑代打，就没有方案可用。建议一次性把牌池补上座位 0 的方案：本地约 17 分钟，自由对局的 1000 副牌和已有游戏都不受影响。这样所有座位都只有一种叫牌方式。
   - **其他选项**：这一种情况用旧的启发式代打；或者现场算 SkatZero 叫牌（生产上每次约 10 秒，会卡住服务）。
   - 牌池在公开仓库里，牌面可以查到；房间不计排名，与自由对局的接受理由相同。
   - **待定**
5. **开局和后来的人**
   - **建议**：
     - 按加入顺序入座，房主坐 0 号；
     - 房主随时可以点「开局」，没人坐的座位由电脑坐满；
     - 开局后不再有人能加入，晚到的人看到「这个房间已经开局」。
   - **理由**：这是最小版本，与现有房间的规则一致。若要支持中途换掉电脑，就得处理「从哪一副开始算分」等问题，可以以后再做。
   - **待定**
6. **连续打多副和累计分**
   - **建议**：
     - 一副结束后，任何一位真人点「下一副」，大家一起开下一副，发牌人顺时针轮转；
     - Seeger-Fabian 累计分显示在信息板的「Gesamt」里，三个座位都显示，电脑也算；
     - 结算面板下面列出本副三人得分和累计分。
   - **待定**
7. **掉线和离开**
   - **建议**：
     - 保持现有规则：断线 30 秒后由电脑代打，重新打开链接就收回座位；
     - 点「Tisch verlassen」与关掉页面相同；
     - 所有真人都离开后，房间 24 小时无活动过期。
   - **待定**
8. **页面、入口和名字**
   - **建议**：
     - `/de/raum`（英文 `/en/room`）是一个公开页面，介绍「和朋友一起打 Skat」，上面有「开房间」按钮。这个页面可以被收录，因为「Skat mit Freunden online spielen」是有搜索量的词。房间页 `/de/raum/<号>` 是个人页面，不收录。
     - 入口放在打牌页的阅读区和第 11 课课后的「下一步」里。页头链接是你定的，这次不动。
     - 昵称规则与排行榜相同（`nickname.ts`），房主建房时也填。电脑座位沿用 Lina / Max 两个名字。
   - **待定**
9. **统计**
   - **建议**：PostHog 记三个事件：`room_created`、`room_joined`、`room_started`（附真人数）。可以看每周开房数、加入率，以及几人局和电脑补位的比例。
   - **待定**

**前提核对**（已查）：
- 网站已有 `MULTIPLAYER_URL` 和 `MULTIPLAYER_ADMISSION_KEY`；生产上 `MULTIPLAYER_URL` 就是 multiplayer 服务公开的 Render 地址，浏览器可以直连。
- 网站没有 CSP 限制连接地址。
- 房间快照结构要改。从这台机器连不上生产库（库只允许白名单 IP），没法查现存房间；但房间以前没有前端，24 小时无活动就会过期，所以生产上应当没有活着的房间。
