# Acceptance

## 1. Incident and Outcome Semantics
Read-only anonymized incident export, replay and diagnostic command must report
184, two player's-side wins over six valid games, and six matching AI seat scores.
Focused cases cover declaration wins, defence wins, all-pass and one-game samples
using the same `recordOf` as the XP board.

## 2. Independent Holdout
Execute the skill's predeclared ordinary-card protocol for all 17 profiles with
three seeds; report unique cards, effective games, role/contract strata and grouped
confidence bounds. Every simultaneous upper bound must be <=0.35. Report the
selected daily-one sample separately and declare limited strata insufficient.

## 3. Paired Distribution Comparison
Run both policy versions on identical holdout cards/seeds and canonical opponents.
Report six-deal replication, all-win frequency, score/XP distributions, tails and
audited errors without filtering results. New population strength and replication
must decline; real ties/upsets remain allowed.

## 4. Authoritative Games and Boards
Replay every sampled game, recalculate summaries and XP, then verify isolated
runner completion and daily/XP reads. Canonical results, human rows/names and the
shared engine/model files remain unchanged.

## 5. Frozen Policy and Expansion
Local restart/retry/config tests verify exact legacy/new policy routing, recorded
decision replay, unchanged completed rows, unchanged daily activity plans, no
duplicate score/XP and retained identity prefixes at 17/100/200/300/400/500.
Configuration gate must reject uncalibrated near-canonical new profiles.

## 6. Skill and Delivery
Validate the skill frontmatter/links and execute documented commands. Record actual
sample sizes, target bands versus observations, selected-mode limits and Berlin
activation behavior. Run the project's required mechanical defence. Review only.
