# SKATGO-48 grill

Grill: self（人在工单上授权全自动，并说「你思考后决定UI」）。依据只有 charter 和实际观察。

1. **牌点和局值怎么得到？** 打完一副时写入摘要。
   - 最初的决定是：已打过的副在读取时重放补齐。
   - 人在 2026-10-06 改为：不写兼容旧记录的代码，线上旧记录全部删除、重新发牌。重放补齐的代码已删除。
   - **决定**：按人的要求。
2. **（作废）补齐数据与原分数一致的问题**：随第 1 题一起取消。
3. **折叠还是横向滚动？** 用折叠。每副一行摘要：局号、你的分和角色、AI 的分和角色、差。点开后显示两边各一行完整结果。打完一副后的弹窗和 `/daily` 中途，最新一副默认展开。
   - 依据：手机 375 宽下，摘要一行放得下；横向滚动会把需要对比的列推出屏幕。
   - **决定**：采纳。
4. **差值要不要用红绿色？** 不用，用正负号加粗。
   - 依据：ui.md 规定 `good` / `bad` 只用于判断答案对错。
   - **决定**：采纳。
5. **设计值注册表的改动**：只把 `dims.vsAiColumns` 改成四列，不新增 token。
   - 依据：人在本工单说「你思考后决定UI」，把 UI 决定交给了机器；改动只限这个组件的网格，在本单内完成。
   - **决定**：采纳，并在工单评论中写明。
6. **每副打完后的那一行「AI 这副怎么打」**：删掉，改为在同一处显示整张对比表，最新一副展开。
   - 依据：工单要求这一处也显示两边结果、分数和差，表格的最新一行已经全部包括。
   - **决定**：采纳。
7. **Null 定约怎么显示？** 只显示胜负，不显示牌点。
   - 依据：Null 不以牌点论胜负。
   - **决定**：采纳。
